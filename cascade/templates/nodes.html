Browser sign-in for TeraBox

Private TeraBox shares need a session cookie. Open Add node, choose TeraBox, and press Sign in with browser. A Chromium window opens on the computer running Cascade, waits for you to sign in, then saves the cookie. The window expires after {{ browser_login_minutes }} minutes.

TeraBox uses a local browser cookie capture because it has no OAuth API for this. Dropbox, Google Drive and OneDrive use provider OAuth instead; their APIs reject session cookies.

This needs Playwright with Chromium on the same machine as Cascade. The cookie is stored in SQLite and never shown on this page.

Adding a node

1. Pick a provider

Local disk is the simplest. S3-compatible, WebDAV, FileBrowser and connected cloud drives can store and upload files. Sign-in is the easiest way to add a cloud drive.

2. Name it

The name is required and only appears in Cascade. Fill every field marked *; fields marked optional can stay blank.

3. Test it

Press Add node, then Test on the card. Edit the node later to add optional settings or rotate credentials.

How routing works

/s/ stream

Cascade pulls bytes from the node and writes them to the visitor, preserving Range requests so video seeks work. Nothing about the source is exposed.

/f/ forward

A 302 to the resolved direct URL. Best for Dropbox, Drive, OneDrive, S3 and TeraBox where the CDN should carry the transfer. Local and WebDAV links fall back to streaming.

Replication

Copies stream node-to-node in the background. Targets must be writable nodes: local disk, FileBrowser, WebDAV, S3-compatible storage or a connected cloud drive.
